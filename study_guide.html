PART I

Verilog RTL, Digital Design & DFT Fundamentals

  • What Software vs. HDL Compiles Into: Software (C/C++/Python) compiles into sequential machine instructions (ISA opcodes) executed step-by-step on a CPU fetch-decode-execute pipeline. HDL (Verilog/SV) elaborates into a concurrent event-driven simulation model and synthesizes into physical spatial hardware gates, multiplexers, flip-flops, and wires connected in a netlist.
  • Parallelism in SW vs. HDL: Software achieves concurrency via OS threads/processes time-sliced across a limited number of CPU cores (requiring locks/mutexes for shared memory). Hardware achieves true spatial parallelism—every always block, continuous assign, and logic gate evaluates simultaneously on every clock edge.
  • wire vs. reg: A wire represents a physical connection that cannot store state; it must be continuously driven by an assign statement or module output port (supports multiple drivers with resolution). A reg stores its last assigned value between procedural assignments inside always/initial blocks—it does not necessarily synthesize to a flip-flop (combinational always @(*) blocks assign to reg and synthesize to combinational gates).
  • Checklist When Bad RTL Outputs XXXX:
    1. Missing or Unasserted Reset: Flip-flops without reset power up to X and circulate X through feedback loops.
    2. Multi-Driven Nets: Two assign statements or two always blocks driving the same signal with 0 and 1 simultaneously resolve to X.
    3. Unconnected Input Ports / Undriven Signals: Floating inputs propagate Z → X through gates.
    4. Out-of-Bounds Array Indexing: Reading mem[addr] where addr is X or exceeds array bounds returns X.
    5. Blocking/NBA Race Conditions or Setup/Hold Violations: Concurrent blocks reading and writing with = on the same clock edge.

SystemVerilog divides each simulation time step into ordered scheduling regions: Preponed (SVA sample) → Active (blocking =, RHS of NBA, $display) → Inactive (#0) → NBA (LHS updates of <=) → Observed (SVA evaluation) → Reactive (TB program) → Postponed ($strobe, $monitor).

blocking_vs_nba_trace.sv — Screening Interview Code Trace 
int a, b, c, d;
initial begin
  a = 1;       // Active: a immediately becomes 1
  b = 5;       // Active: b immediately becomes 5
  b <= a + 1;  // Active: evaluates RHS (1 + 1 = 2), schedules b = 2 in NBA region
  a <= 10;     // Active: evaluates RHS (10), schedules a = 10 in NBA region
  c = a + b;   // Active: uses CURRENT Active values (a=1, b=5) -> c = 6 immediately!
  d <= b + c;  // Active: uses CURRENT Active values (b=5, c=6) -> schedules d = 11 in NBA!
end
// Final values after NBA region completes: a = 10, b = 2, c = 6, d = 11

Delaying input a by one clock cycle into a_d and taking a ^ a_d (combinational, 0-cycle latency) or registering pulse <= a ^ a_d (1-cycle registered output) generates a clean 1-clock-wide pulse on every rising or falling toggle of a:

toggle_pulse_detector.v 
module toggle_edge_detector (
  input  logic clk,
  input  logic rst_n,
  input  logic a,
  output logic pulse_comb, // Immediate 1-cycle pulse when 'a' changes
  output logic pulse_reg   // Registered 1-cycle pulse (glitch-free output)
);
  logic a_prev;

  always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
      a_prev    <= 1'b0;
      pulse_reg <= 1'b0;
    end else begin
      a_prev    <= a;
      pulse_reg <= (a ^ a_prev); // High for 1 clock cycle whenever a toggles (0->1 or 1->0)
    end
  end

  assign pulse_comb = a ^ a_prev;
endmodule
  • N-Bit Ring Counter: A circular shift register initialized to a one-hot state (e.g., 4'b0001) feeding q[N-1] back to q[0]. It cycles through N states and reverts to its initial state after N clock cycles (N × T_clk).
  • Johnson (Twisted Ring) Counter: Feeds the inverted MSB (~q[N-1]) back to q[0], cycling through 2N states and reverting after 2N clock cycles.
  • Frequency Divider by 2 & 4: A synchronous 2-bit binary up-counter produces a 50%-duty-cycle divide-by-2 clock on cnt[0] and a 50%-duty-cycle divide-by-4 clock on cnt[1] without ripple-clock skew.
clk_div_2_4.v 
module clk_div_2_4 (
  input  logic clk,
  input  logic rst_n,
  output logic clk_div2,
  output logic clk_div4
);
  logic [1:0] cnt;

  always_ff @(posedge clk or negedge rst_n) begin
    if (!rst_n)
      cnt <= 2'b00;
    else
      cnt <= cnt + 2'b01; // Cycles 00 -> 01 -> 10 -> 11 -> 00
  end

  assign clk_div2 = cnt[0]; // Toggles every 1 clk  -> f_clk / 2 (50% duty cycle)
  assign clk_div4 = cnt[1]; // Toggles every 2 clks -> f_clk / 4 (50% duty cycle)
endmodule

1. Identifying Module X (3-Bit Galois LFSR) & First 5 Outputs

Given n1 = q3 ^ q1, out = {q3, q2, q1}, reset seed {q3,q2,q1} = 3'b111, and next-state equations q1 <= q3; q2 <= q3 ^ q1; q3 <= q2;:

  • Hardware Synthesized: Three D flip-flops with asynchronous active-low preset (rst_n) and one 2-input XOR gate feeding q2 — a 3-bit maximal-length Galois Linear Feedback Shift Register (LFSR) (polynomial x^3 + x + 1, period 2^3 - 1 = 7).
  • First 5 Outputs After Reset Release: Reset: 111 (7) → Clk 1: 101 (5) → Clk 2: 001 (1) → Clk 3: 010 (2) → Clk 4: 100 (4) → Clk 5: 011 (3).

2. Bugs, Poor Coding Practices & Critical Path in module test

  • Syntax / Compilation Bugs: posedgeclk missing space; out driven via <= inside always @(posedge clk) without declaring output reg [2:0] out; r1, r2, r3 undeclared; port mismatch instantiating .pre_n(pre_n) when module X defines rst_n.
  • Blocking Assignments in Sequential Logic: r1 = 1'b1; r2 = r1; r3 = r2; uses blocking = inside a clocked always block, collapsing 3 shift-register stages into a single constant 3'b111 wire!
  • Critical Path Analysis: Longest register-to-register path is from DUT.q3 / DUT.q1 → XOR gate (n1) → 4:1 MUX (select) → out[2:0] flip-flop D-input (T_clk-to-q + T_xor + T_mux + T_setup).
  • 1. Controllability & Observability on G = ((A & B) & C) | D (Nets E = A & B, F = E & C): To observe internal nodes E and F at output G, set non-controlling values on downstream gates: D = 0 (so OR gate passes F) and C = 1 (so second AND gate passes E).
    • Test E Stuck-At-0 (SA0) & F SA0: Apply (A,B,C,D) = (1,1,1,0) → fault-free G = 1; if E or F is SA0, G = 0.
    • Test E Stuck-At-1 (SA1) ONLY (isolating E): Apply (A,B,C,D) = (0,1,1,0) (or (1,0,1,0)) → fault-free E = 0, F = 0, G = 0; if E is SA1, E = 1 → F = 1 → G = 1.
  • 2. Catching Stuck-At-0 on Write-Back Data Bus LSB (with 256 KB 8-Way Cache, 64B Line): Store an odd integer (e.g., 0x0000_0001) to memory address Addr_A (writes to cache / evicts dirty line through the WB data bus), then evict that cache set by reading 8 distinct conflict addresses mapping to the same set index (forcing a write-back to main memory), and finally reload Addr_A and check if bit [0] became 0.
  • 3. At-Speed Transition Faults on an AND Gate: Static truth-table vectors only verify steady-state DC logic. To catch slow-to-rise / slow-to-fall propagation delay defects, you need two-pattern transition test vectors (V1 → V2) launched and captured at full functional clock speed (Launch-on-Capture / Launch-on-Shift)—for example, holding B = 1 while transitioning A: 0 → 1 and A: 1 → 0 within one functional clock period T_clk.
  • ~A Using a NAND Gate: Tie both inputs together (NAND(A, A) = ~(A & A) = ~A) or tie one input to logic 1 (NAND(A, 1) = ~A).
  • Boolean Reduction (~A·B + A·B·C + ~C·B): Factor out B: B · (~A + A·C + ~C). Since A·C + ~C = A + ~C, we get B · (~A + A + ~C) = B · (1 + ~C) = B.
  • XOR Using AND / OR / NOT Only: A ^ B = (A & ~B) | (~A & B) (requires 2 NOT gates, 2 AND gates, and 1 OR gate).
  • 4-Bit BCD Input (D[3:0], 0..9) × 5 Output (0..45):
    • Binary Output (Y[5:0] = 5 × D): Since 5 × D = (4 × D) + D = (D << 2) + D, shift D left by 2 bits and add D using a 4-bit ripple-carry adder (since LSBs Y[1:0] = D[1:0] pass straight through with zero gates!).
    • BCD Output (Tens[3:0], Ones[3:0]): Notice that multiplying any decimal digit D by 5 always ends in 0 (when D is even) or 5 (when D is odd), while the Tens digit is simply D >> 1 (floor(D / 2))! Thus, Tens = {1'b0, D[3:1]} and Ones = {1'b0, D[0], 1'b0, D[0]} (0 gates—pure wiring!).

sv_bit_and_array_coding.sv 
// Problem A: Pack all 1s in a 32-bit integer to the MSB positions
// Example: 32'h00E1_0F00 (8 ones) -> 32'hFF00_0000
function automatic bit [31:0] pack_ones_to_msb(bit [31:0] din);
  int ones = $countones(din); // Built-in SV system function!
  if (ones == 0) return 32'h0;
  // Create 'ones' 1s at LSB via (1 << ones) - 1, then left-shift to MSB:
  return ((64'd1 << ones) - 1) << (32 - ones);
endfunction

// Problem B: Single-pass O(N) 2nd largest element in an array (handles duplicates)
function automatic int find_second_largest(int arr[]);
  int max1 = -32'sh7fff_ffff - 1;
  int max2 = -32'sh7fff_ffff - 1;

  foreach (arr[i]) begin
    if (arr[i] > max1) begin
      max2 = max1;
      max1 = arr[i];
    end else if (arr[i] > max2 && arr[i] != max1) begin
      max2 = arr[i];
    end
  end
  return max2;
endfunction

// Problem C: Byte/Word Slicing into Dynamic Arrays A[] and B[]
// Pattern: A[0]=a[7:0], B[0]=a[15:0], A[1]=a[23:16], A[2]=a[31:24], ...
function automatic void slice_vector #(parameter int P = 31) (
  input  logic [P:0]  a,
  output logic [7:0]  A[],
  output logic [15:0] B[]
);
  int num_bytes = (P + 1) / 8;
  A = new[num_bytes - 1];
  B = new[1];
  B[0] = a[15:0];
  A[0] = a[7:0];
  for (int b = 2; b < num_bytes; b++) begin
    A[b - 1] = a[b*8 +: 8]; // Indexed part-select [lsb +: width]
  end
endfunction
Feature function task
Simulation Time Must execute in 0 simulation time (no direct #, @, or wait). Can consume simulation time (#delay, @(event), wait()).
Return Value Returns 1 value via function name or return (or void). No return value; uses output / inout / ref arguments.
Calling Rules Can call functions; can only spawn tasks via fork...join_none. Can call both tasks and functions freely.

Can You Put a Timing Event in a Function, or Inside fork...join Inside a Function?

Directly or inside fork...join / fork...join_any: NO (compile error, because join and join_any block the function in time). Inside fork...join_none: YES! Because join_none schedules the child process and returns immediately in 0 time, IEEE 1800 SystemVerilog explicitly allows timing delays and task calls inside fork...join_none inside a function.

  • Pass by ref & const ref: Passes a pointer/reference rather than copying large dynamic arrays/queues on subroutine entry/exit—boosting simulation speed and letting tasks observe live variable updates. Requires an automatic task/function (default inside classes).
  • static vs. automatic Lifetime: Module/interface/program tasks and functions default to static storage (shared across concurrent calls unless declared automatic); class methods and local variables default to automatic (per-call stack allocation).
  • 1. Nested fork begin ... end join Guard Around disable fork: Calling disable fork; directly kills all child threads spawned by the current parent process—including earlier background monitors launched via fork...join_none. Wrapping your fork...join_any + disable fork; inside an outer fork begin ... end join isolates the scope so disable fork only terminates the inner sibling threads! Also, inside a fork...join_any watchdog, always check which branch finished (e.g., if (timeout_occurred)) before printing a timeout error—otherwise a valid ready == 1 at #45 still falls through to the line after join_any!
  • 2. Event Race Condition (@(e1) vs. wait(e1.triggered)): If Thread 1 triggers -> e1; at #5 and Thread 2 waits until #10 before executing @(e1);, Thread 2 hangs forever because -> e1 is an instantaneous pulse that already passed at #5. Even in the same time slot, wait(e1.triggered) is level-sensitive for the entire time step and avoids race conditions with -> e1.
  • 3. Semaphore (new(1)) Timing Puzzle: With 1 key shared by 2 tasks inside fork...join (each doing get(1); $display; #10; put(1);): Task 1 prints at t=0 and puts key at t=10; Task 2 wakes at t=10, prints at t=10, and puts key at t=20. After #50, both displays have already printed and 1 key is available.
wait_n_cycles_watchdog.sv — Safe Isolated Watchdog 
task automatic wait_for_sig_with_timeout(int max_cycles, output bit timed_out);
  timed_out = 1'b0;
  fork begin // Outer guard isolates 'disable fork' to only the two threads below
    fork
      begin
        @(posedge vif.clk iff (vif.ready === 1'b1));
      end
      begin
        repeat (max_cycles) @(posedge vif.clk);
        timed_out = 1'b1;
      end
    join_any
    disable fork;
  end join
endtask

Four Pillars of OOP in SV

  • Encapsulation: Bundles fields & methods inside a class; controls visibility via public, protected (class + subclasses), and local (declaring class only).
  • Inheritance: class child extends parent; reuses fields, methods, and constraints without touching base code.
  • Polymorphism: Base handle points to derived object and dynamically dispatches overridden virtual methods at runtime.
  • Abstraction: virtual class + pure virtual methods define a strict contract without allowing direct instantiation.

Applications of Polymorphism

  • Real-World Software Example: A payment checkout engine calls payment_method.process(amount) on a generic PaymentMethod handle—at runtime, CreditCard, UPI, or PayPal executes its own gateway logic without if/else branching.
  • Silicon Verification (UVM) Example: A generic Driver, Monitor, or Scoreboard operates on base_pkt handles calling pkt.pack() or pkt.calc_crc(). When a test uses a UVM Factory override to substitute corrupt_crc_pkt or jumbo_pkt, the environment automatically runs the derived behavior with zero changes to the driver or scoreboard!
virtual_polymorphism_cast.sv 
virtual class BasePkt;
  rand bit [31:0] addr;
  pure virtual function bit [31:0] calc_crc();
  virtual function void display();
    $display("[BASE] addr = 0x%08h", addr);
  endfunction
endclass

class ErrPkt extends BasePkt;
  rand bit bad_crc;
  virtual function bit [31:0] calc_crc();
    return bad_crc ? 32'hDEAD_BEEF : ~addr;
  endfunction
  virtual function void display();
    $display("[ERR]  addr = 0x%08h bad_crc = %0b", addr, bad_crc);
  endfunction
endclass

initial begin
  BasePkt base_h;
  ErrPkt  err_h = new(), cast_h;
  void'(err_h.randomize());

  base_h = err_h;     // Upcasting: always legal
  base_h.display();   // Calls ErrPkt::display() because display() is 'virtual'

  // Downcasting: required to access child-only member 'bad_crc' from base_h
  if ($cast(cast_h, base_h))
    $display("Downcast succeeded: bad_crc = %0b", cast_h.bad_crc);
end

// 1. Sorted array & Unique array with min difference >= 5 in [1:100]
class array_constraints;
  rand bit [7:0] sorted_arr[10];
  rand int       spaced_arr[10];

  constraint c_sorted {
    foreach (sorted_arr[i])
      if (i > 0) sorted_arr[i] > sorted_arr[i-1];
  }

  constraint c_unique_spaced {
    unique {spaced_arr};
    foreach (spaced_arr[i]) {
      spaced_arr[i] inside {[1:100]};
      foreach (spaced_arr[j])
        if (i < j)
          (spaced_arr[i] - spaced_arr[j] >= 5) || (spaced_arr[j] - spaced_arr[i] >= 5);
    }
  }
endclass

// 2. Fibonacci Sequence of Length N
class fib_seq;
  rand int unsigned fib[];
  int N = 10;

  constraint c_fib {
    fib.size() == N;
    foreach (fib[i]) {
      if (i == 0)      fib[i] == 0;
      else if (i == 1) fib[i] == 1;
      else             fib[i] == fib[i-1] + fib[i-2];

// 3. Size-Aligned Address & 80% Cache Hit Ratio on Lower 5 Bits
class cache_mem_txn;
  rand bit [31:0] addr;
  rand bit [1:0]  size; // 0=1B, 1=2B, 2=4B, 3=8B
  rand bit        hit;  // 1=hit (80%), 0=miss (20%)
  bit [4:0]       prev_index;

  constraint c_align_and_hit {
    (size == 1) -> (addr[0]   == 1'b0);
    (size == 2) -> (addr[1:0] == 2'b00);
    (size == 3) -> (addr[2:0] == 3'b000);

    solve hit before addr;
    hit dist { 1'b1 := 80, 1'b0 := 20 };
    (hit == 1'b1) -> (addr[4:0] == prev_index);
    (hit == 1'b0) -> (addr[4:0] != prev_index);
  }

  function void post_randomize();
    prev_index = addr[4:0];
  endfunction
endclass

Scoreboard Mailbox Comparison & Bug Spotting: In the NVIDIA screening snippet, if (exp.data = act.data && exp.id = act.id) uses assignment (=) instead of equality (==), overwriting exp so the check always evaluates true whenever act.data != 0! Also, $random returns signed 32-bit integers (so negative values make repeat(time_count) execute 0 times—use $urandom_range(1, 5)). For out-of-order DUTs, store expected transactions in an associative array indexed by id (exp_aa[act.id]) instead of a strict FIFO mailbox.
  • 2. Multi-Source to Single-Destination Arbiter Permutations: When src_0 requests dst_0 (id=0 at t=0, id=2 at t=1) and src_1 requests dst_0 (id=1 at t=0), per-source FIFO ordering requires id=0 to precede id=2. Thus, out of 3! = 6 permutations, only the 3 valid arrival sequences at dst_0 are {0, 1, 2}, {1, 0, 2}, and {0, 2, 1}—which a scoreboard models using per-source queues (src_q[0], src_q[1]) and checking that any granted transaction matches the head (src_q[src_id][0]) of its originating source queue!
apb_if_driver_sva.sv 
interface apb_if (input logic pclk, input logic presetn);
  logic [31:0] paddr, pwdata, prdata;
  logic        psel, penable, pwrite, pready, pslverr;

  // SVA 1: SETUP phase (PSEL && !PENABLE) must transition to ACCESS (PSEL && PENABLE) next cycle
  property p_setup_to_access;
    @(posedge pclk) disable iff (!presetn)
    (psel && !penable) |=> (psel && penable);
  endproperty
  assert property (p_setup_to_access) else $error("APB SETUP->ACCESS violation");

  // SVA 2: During ACCESS wait states (!PREADY), PSEL, PENABLE, PADDR, PWRITE, PWDATA stay stable
  property p_access_stability;
    @(posedge pclk) disable iff (!presetn)
    (psel && penable && !pready) |=> (psel && penable && $stable({paddr, pwrite, pwdata}));
  endproperty
  assert property (p_access_stability) else $error("APB signal changed during wait state");

  // SVA 3: Once PREADY asserts in ACCESS, PENABLE must de-assert on the next cycle
  property p_access_completion;
    @(posedge pclk) disable iff (!presetn)
    (psel && penable && pready) |=> !penable;
  endproperty
  assert property (p_access_completion) else $error("APB PENABLE stuck high after PREADY");
endinterface

// APB Master Driver Task (SETUP -> ACCESS -> Wait for PREADY)
task automatic drive_apb_transfer(virtual apb_if vif, bit [31:0] addr, bit [31:0] data, bit write);
  @(posedge vif.pclk);
  vif.psel    <= 1'b1;
  vif.penable <= 1'b0; // SETUP phase
  vif.paddr   <= addr;
  vif.pwrite  <= write;
  vif.pwdata  <= data;

  @(posedge vif.pclk);
  vif.penable <= 1'b1; // ACCESS phase

  do @(posedge vif.pclk); while (!vif.pready); // Hold until PREADY == 1

  vif.psel    <= 1'b0;
  vif.penable <= 1'b0;
endtask

  • Shallow Copy (p2 = new p1;) vs. Deep Copy (p2.copy(p1);): Shallow copy allocates a new outer object and copies primitive properties, but copies only the handle of any nested sub-object—so mutating p2.hdr.id corrupts p1.hdr.id. A Deep Copy explicitly allocates and copies every nested sub-object so both hierarchies are completely independent in memory.
  • Parent Class Access (super): Inside a derived class, super.new(...) invokes the parent constructor (must be the first statement if the parent new() takes arguments), and super.method() invokes the parent's overridden method or property.
  • for { fork ... join } Loop Variable Trap (automatic): In a for loop spawning threads with fork...join_none (or join_any), the loop iterator i is shared across all spawned threads—so without capturing an automatic copy inside each iteration, every thread observes the final value of i!

  • Ascending Order Constraint: Use foreach (arr[i]) if (i > 0) arr[i] > arr[i-1]; for strictly ascending values (or >= for non-decreasing order).
  • soft Constraints: A soft constraint provides a default rule that the solver automatically drops if a higher-priority hard constraint or inline randomize() with { ... } conflicts with it—preventing constraint-conflict failures.
  • How to Know If randomize() Succeeded or Failed: obj.randomize() is a built-in function returning int: 1 on success and 0 on failure (e.g., conflicting constraints). On failure, all rand variables retain their previous values and post_randomize() is skipped. Always check if (!obj.randomize()) `uvm_fatal(...) (never ignore the return value with void'() in production tests).
  • What If There Are NO Constraints in the Class? randomize() still works! Every rand variable is assigned a uniformly distributed random value across its full legal bit-width domain (e.g., 0..255 for bit [7:0]), and randomize() returns 1 (provided no rand_mode(0) issue or external inline conflict exists).

class bit_count_constraints;
  rand bit [31:0] myvec1;
  rand bit        myvec2[32];
  rand bit        dyn5[];

  // a) At least 10 and no more than 18 bits set to 1
  constraint c_myvec1 {
    $countones(myvec1) inside {[10:18]};
  }

  // b) More than 5 ones in myvec2, and strictly fewer ones than myvec1
  constraint c_myvec2 {
    myvec2.sum() with (int'(item)) > 5;
    myvec2.sum() with (int'(item)) < $countones(myvec1);
  }

  // c) Dynamic array of size 5 with exactly three 1s and two 0s
  constraint c_dyn5 {
    dyn5.size() == 5;
    dyn5.sum() with (int'(item)) == 3;
  }
endclass
  • Enumerated Types (typedef enum bit [1:0] {RED, YELLOW, GREEN} light_e;): Provide strong type checking (assigning an undeclared name or raw integer without $cast/cast fails compilation). Always specify an explicit bit width (default is 32-bit int). Built-in methods: first(), last(), next(n), prev(n), num(), and name().
  • Packed vs. Unpacked struct: A struct packed (optionally signed) stores members as a contiguous bit vector supporting bit/part-slicing and bitwise/arithmetic ops. An unpacked struct (default) stores fields independently; slicing the whole struct is illegal.
  • clocking Block vs. modport (Why Both Are Needed): A clocking block defines synchronous sampling (input #1step) and driving (output #0) skews to prevent TB/DUT race conditions—but it is non-synthesizable and only applies to synchronous signals. A modport is synthesizable, enforces port directions (input/output) on RTL modules, and bundles asynchronous signals (like rst_n) alongside clocking blocks into a single interface port view.
  • Inheritance Handle Puzzle (class B extends A; int ab; endclass with A a0; B b0, b1;):
    1. a0 = b0; — Legal (Upcasting): Base handle a0 points to the B object (ensure b0 = new(); is called first).
    2. Can we access a0.ab? — No (Compile Error): Member lookup uses the handle's declared type (A), which has no property ab. However, ab still exists intact in memory inside the underlying B object!
    3. $cast(b1, a0); & b1.ab: — Succeeds (Dynamic Downcasting): Because a0 points to a B instance at runtime, $cast(b1, a0) returns 1 and b1.ab can now be read/written directly (or accessed via a virtual getter method declared in A).
  • 99-Element Memory Where 49 Values Repeat in Pairs and 1 Value Is Unique: XOR all 99 elements together (res ^= mem[i]) in O(N) time and O(1) space—every duplicate pair cancels (x ^ x == 0), leaving only the single non-repeated element! (If elements can repeat 3+ times, count frequencies in an associative array int freq[int];).

Sequence ↔ Driver Handshake: Sequence calls start_item(req) (waits for sequencer arbitration) → randomizes req → calls finish_item(req). Driver unblocks from seq_item_port.get_next_item(req), drives DUT pins, and calls item_done() to unblock finish_item().

Key Design Details: (1) Declare the base class's 32-byte alignment constraint with the same constraint name (or soft) so the derived class overrides it cleanly to 16-byte alignment (addr[3:0] == 4'h0) without a solver contradiction. (2) Guarantee globally unique tid values across concurrent sequences running on the same sequencer using a static atomic counter (or sequencer-owned ID pool).

  • uvm_component vs. uvm_object: Components (uvm_env, uvm_agent, uvm_driver, uvm_monitor, uvm_scoreboard) are quasi-static structural blocks created in build_phase that persist for the entire simulation, execute UVM phases, and form a parent-child hierarchy (new(name, parent)). Objects (uvm_sequence_item, uvm_sequence, config objects) are transient data/stimulus items created dynamically (new(name)) with no phases or hierarchy.
  • Why Components Have Hierarchy: Enables deterministic top-down build_phase configuration, bottom-up connect_phase wiring, scoped uvm_config_db lookups, and path-targeted Factory instance overrides.
  • m_sequencer vs. p_sequencer: Calling seq.start(sqr) binds the sequence to sqr and sets its built-in uvm_sequencer_base handle m_sequencer. Declaring `uvm_declare_p_sequencer(my_sqr) downcasts m_sequencer into p_sequencer so the sequence can directly access custom config/RAL handles inside my_sqr.
  • TLM port vs. export vs. imp: A port initiates TLM calls (put()/get()); an export routes/forwards TLM calls across component hierarchy boundaries; an imp (implementation port) terminates the connection and actually implements the interface task/function.
  • copy(rhs) vs. clone(): dst.copy(src) deep-copies fields into an already-constructed destination object. src.clone() allocates a new object via the UVM Factory (create()), calls copy(src), and returns a uvm_object handle (requiring $cast(dst, src.clone())). Both prevent handle-aliasing corruption when storing transactions in scoreboard queues or broadcasting across analysis ports.
  • Advantages (and Trade-Offs) of `uvm_field_int / `uvm_field_object Macros: Automatically implement copy(), compare(), print(), pack(), unpack(), and record() with minimal code—though high-performance VIPs often implement do_copy() and do_compare() directly to avoid macro expansion compile overhead.
PART IV

Computer Architecture, Cache Coherency, Scripting & Behavioral

  • 7 Dependent ADD/SUB Instructions in a 4-Stage Pipeline (IF → ID → EX → WB):
    • With EX-to-EX Forwarding (10 Cycles): ALU results bypass directly from EX to the next instruction's EX input → 0 stalls. Completion cycles: I1=4, I2=5, I3=6, I4=7, I5=8, I6=9, I7=10.
    • Without Forwarding (22 Cycles; or 16 Cycles with split-cycle RF): Each dependent instruction stalls in ID until the producer finishes WB (2 stall bubbles per RAW pair → 10 + 6×2 = 22 cycles; or 1 stall bubble if RF writes in first half of WB and reads in second half of ID → 10 + 6 = 16 cycles).
  • Three Types of Data Hazards & Mitigations:
    • RAW (Read-After-Write — True Dependency): Mitigated via EX/MEM forwarding (bypassing), hazard-detection stalls (for Load-Use hazards), and compiler instruction scheduling.
    • WAR (Write-After-Read — Anti-Dependency) & WAW (Write-After-Write — Output Dependency): Occur in out-of-order / superscalar pipelines; eliminated via Register Renaming (Tomasulo's algorithm / ROB physical register tags).
  • Write-Through vs. Write-Back: Write-Through updates both the cache and lower memory on every store—simpler coherency, zero dirty-eviction latency, but consumes high memory bandwidth. Write-Back writes only to the cache and sets a dirty bit, writing the 64B line back to L2/DRAM only upon eviction—better for high-performance CPUs because repeated writes to the same cache line coalesce without saturating bus bandwidth.
  • MESI Cache Line Trace (32 KB Cache, 2-Way Set Associative, 64B Line):
    Offset bits = log2(64) = 6 bits [5:0]; Number of sets = 32,768 / (2 × 64) = 256 sets → Set Index = 8 bits [13:6]; Tag = bits [31:14].
    1. Read 0x010F30: Set Index = 0x3C, Tag = 0x04, Offset = 0x30. Cold cache miss → fetches 64B block (0x010F00..0x010F3F) into Way 0. Assuming no other core holds a copy, line enters Exclusive (E) (or Shared (S) if another core caches it).
    2. Write 0x880F00: Set Index = 0x3C (same set!), Tag = 0x220. Write miss → allocates into Way 1 (no eviction needed since Set 0x3C is 2-way), broadcasts Read-For-Ownership (RFO), and transitions Way 1 line to Modified (M).
    3. Write 0x010F20: Set Index = 0x3C, Tag = 0x04 (falls inside the 64B line already loaded in Way 0!). Cache Hit! Way 0 silently upgrades from Exclusive (E) → Modified (M) without bus traffic (or issues an invalidate if it was S).

# 0. Reverse a Singly Linked List in O(N) Time and O(1) Space
def reverse_linked_list(head):
    prev, curr = None, head
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt
    return prev

# 1. Shortest Path in Binary Grid (BFS) — returns edge distance (6 for 4x4 (0,0)->(3,3))
def shortest_path(grid: list[list[int]], start: tuple[int, int], end: tuple[int, int]) -> int:
    rows, cols = len(grid), len(grid[0])
    if grid[start[0]][start[1]] == 1 or grid[end[0]][end[1]] == 1:
        return -1
    q = deque([(start[0], start[1], 0)])
    visited = {start}
    while q:
        r, c, dist = q.popleft()
        if (r, c) == end:
            return dist
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 0 and (nr, nc) not in visited:
                visited.add((nr, nc))
                q.append((nr, nc, dist + 1))
    return -1

# 2. Check if an integer is a palindrome without converting to string
def is_palindrome_int(x: int) -> bool:
    if x < 0 or (x % 10 == 0 and x != 0):
        return False
    rev_half = 0
    while x > rev_half:
        rev_half = rev_half * 10 + x % 10
        x //= 10
    return x == rev_half or x == rev_half // 10

# 3. Execute commands from input file & write ERROR / FAILURE lines to output file
def run_and_extract_errors(cmd_file: str, err_file: str) -> None:
    pat = re.compile(r"\b(ERROR|FAILURE|UVM_ERROR|UVM_FATAL)\b", re.IGNORECASE)
    with open(cmd_file) as fin, open(err_file, "w") as fout:
        for cmd in filter(None, map(str.strip, fin)):
            res = subprocess.run(cmd, shell=True, stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True)
            for line in res.stdout.splitlines():
                if pat.search(line):
                    fout.write(f"[{cmd}] {line}\n")
