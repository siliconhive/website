Mastering AXI ACE: The Definitive Guide to Cache Coherence

A full technical teardown of the ARM AMBA 4 ACE protocol—covering MOESI state transitions, AxSNOOP transaction encodings, AxCACHE/AxDOMAIN gating signals, and UVM snoop scoreboard verification.

In high-performance multi-core SoCs, maintaining data consistency across private L1/L2 caches isn't optional. Hardware cache coherence ensures every core and coherent accelerator observes a unified view of shared memory without software cache-flush overhead.

Why Hardware Cache Coherence Matters

  • Prevents silent data corruption: Eliminates stale reads in multi-threaded and producer-consumer workloads.
  • Lowers latency by 10–100×: Direct cache-to-cache snoop transfers avoid round-trips to external LPDDR/DDR DRAM.
  • Reduces memory controller power: Fewer off-chip DRAM activations save substantial system power.

1. The MOESI Coherence Engine

AMBA 4 ACE extends AXI4 with three dedicated snoop channels—AC (Snoop Address), CR (Snoop Response), and CD (Snoop Data)—to manage cache lines across five MOESI states:

StateFull NameClean / DirtyShared / UniqueVerification Key
MModifiedDirtyUniqueExclusive & dirty; must write back to memory or forward on snoop.
OOwnedDirtySharedShared & dirty; responsible for supplying dirty data to snoopers.
EExclusiveCleanUniqueClean & unique; can silently upgrade to M on local store without bus broadcast.
SSharedCleanSharedClean & shared; read-only copies exist across multiple caches.
IInvalid——Not present in cache; any access triggers a snoop or memory fetch.

2. AxSNOOP Encoding: The Command Center

ARSNOOP[3:0] — Coherent Read Transactions

Binary ValueTransactionSnoop & Cache State Effect
0000ReadNoSnoopNon-coherent read; bypasses snoop filter.
0001ReadOnceCoherent snapshot read without allocating into requester's cache.
0100ReadSharedRequests shared copy; peer caches transition M/E → S (or O) and supply data.
0101ReadUniqueRequests ownership for store; peer caches invalidate copies (→ I).
0111CleanUniqueInvalidates peer copies before upgrading an existing shared line to unique.

AWSNOOP[2:0] — Coherent Write Transactions

Binary ValueTransactionSnoop & Cache State Effect
000WriteNoSnoopNon-coherent write directly to downstream memory.
001WriteUniqueInvalidates peer caches first, then writes partial/full line to memory.
011WriteBackEvicts a dirty line (M/O → I) back to main memory.
100EvictSignals clean line eviction so the snoop filter clears directory tracking.

3. The Gating Signals: AxCACHE & AxDOMAIN

AxCACHE[3:0]

Bit[1] (Modifiable) is the master coherence switch: if AxCACHE[1] == 1'b0, the transaction is Non-Modifiable and the ACE interconnect ignores coherence snooping.

AxDOMAIN[1:0]

  • 2'b00: Non-shareable — Private to a single master; no snoops broadcast.
  • 2'b01: Inner Shareable — Coherent across the local CPU cluster.
  • 2'b10: Outer Shareable — Coherent across the wider SoC system (including coherent DMA/NPU).
  • 2'b11: System / Illegal — Reserved/illegal for standard ACE coherent transactions; must be flagged by SVA.
Verification & UVM Scoreboard Tip Deadlocks in ACE subsystems frequently hide in the CD (Snoop Data) and RACK/WACK handshake acknowledgments—a master must never block an incoming ACVALID snoop while waiting for an outstanding ARVALID/AWVALID response. In your UVM scoreboard, track the M → S and M → O dirty-data handoffs carefully, and assert that 3-bit AWSNOOP is never driven from a truncated 4-bit signal. 
// Concurrent SVA: Flag illegal AxDOMAIN == 2'b11 on coherent ACE reads
property p_ace_legal_domain;
  @(posedge aclk) disable iff (!aresetn)
  (arvalid && arready && arcache[1]) |-> (ardomain != 2'b11);
endproperty
assert property (p_ace_legal_domain) else $error("Illegal AxDOMAIN 2'b11 on coherent read!");
