SystemVerilog Assertions (SVA) — A Comprehensive Guide

Master immediate vs. concurrent assertions, overlapping and non-overlapping implication operators, temporal sequence delays, repetition operators, and protocol checker patterns.

SystemVerilog Assertions (SVA) embed executable specification rules directly alongside RTL and testbench interfaces. In both simulation and formal verification, SVA catches protocol violations at the exact clock cycle they occur—eliminating hours of backward waveform tracing.

1. Immediate vs. Concurrent Assertions

FeatureImmediate AssertionConcurrent Assertion
ExecutionProcedural (executed inline like an if statement).Clock-sampled temporal evaluation across multiple clock cycles.
Scheduling RegionEvaluates in the Active region (can glitch on combinational deltas).Samples inputs in the Preponed region; evaluates in Observed region (glitch-free).
Syntaxassert (expr) else $error(...);assert property (@(posedge clk) ...);
Best Use CaseChecking zero-time invariants, function arguments, or UVM randomization results.Bus handshakes (AXI, APB), FIFO overflow/underflow, FSM transitions, and latency bounds.

2. Implication Operators: |-> vs. |=>

An implication separates an assertion into an antecedent (trigger condition) and a consequent (expected behavior). If the antecedent is false, the property passes vacuously:

  • Overlapping Implication (|->): Consequent evaluation begins on the exact same clock cycle that the antecedent completes.
  • Non-Overlapping Implication (|=>): Consequent evaluation begins on the next clock cycle (equivalent to |-> ##1).

4. Production Protocol SVA Examples

// 1. AXI / Valid-Ready Payload Stability Rule
property p_valid_ready_hold;
  @(posedge clk) disable iff (!rst_n)
  (valid && !ready) |=> (valid && $stable(data));
endproperty
a_valid_ready_hold: assert property (p_valid_ready_hold)
  else $error("Protocol violation: valid or data changed before ready!");

// 2. Request-Grant Handshake with Bounded Timeout & Stability
property p_req_gnt_handshake;
  @(posedge clk) disable iff (!rst_n)
  $rose(req) |-> (req throughout (##[1:5] gnt));
endproperty
a_req_gnt_handshake: assert property (p_req_gnt_handshake)
  else $error("Handshake violation: gnt missed window or req dropped early!");

// 3. Cover Property to Prove the Scenario Actually Exercised in Regression
c_req_gnt_handshake: cover property (p_req_gnt_handshake);
Interview Best Practice: Always Pair assert with cover property An assertion that never triggers passes vacuously 100% of the time. Always write a matching cover property for every complex temporal sequence so your coverage report proves the stimulus actually exercised the antecedent!
